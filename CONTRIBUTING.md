# Contributing

Thank you for your interest in contributing to the Arduino Maze Solver Robot project!

## Project Status

This project has been completed and is no longer under active development. It was created as part of the UCI ICS Intelligent Robotics Summer Academy and completed with a 1st Place finish in the final maze competition.

While contributions, suggestions, and improvements are welcome, I will only be actively reviewing and addressing issues that are critical, such as major documentation errors or problems that prevent the project from functioning as intended.

New features, performance improvements, or large changes may not be actively maintained.

## Reporting Bugs

If you discover a critical issue, please open an issue and include as much information as possible, such as:

- A clear description of the problem
- Steps to reproduce the issue
- The expected behavior
- The actual behavior
- Any relevant hardware or software details (for example, Arduino IDE version or board configuration)

Providing detailed information makes it easier to investigate and resolve issues.

## Suggesting Enhancements

Suggestions and improvement ideas are welcome. When submitting a suggestion, please explain:

- What you would like to improve
- Why the change would be beneficial
- Any additional context or examples that may help

Please keep in mind that new features and major changes may not be implemented due to the project's completed status.

## Submitting Changes

If you would like to contribute code or documentation:

1. Fork the repository.
2. Create a new branch for your changes.
3. Make your changes and test them whenever possible.
4. Commit your work with clear, descriptive commit messages.
5. Open a pull request describing what you changed and why.

Please keep changes focused and avoid combining unrelated updates into a single pull request.

## Documentation

Documentation is an important part of this project. If your changes affect the robot's hardware, software, or behavior, please update the relevant documentation so it remains accurate.

## Code Style

When contributing code, please aim to:

- Write clear and readable code.
- Use meaningful variable and function names.
- Include comments where they improve understanding.
- Keep formatting consistent with the existing codebase.

## Code of Conduct

By participating in this project, you agree to follow the guidelines outlined in the [Code of Conduct](CODE_OF_CONDUCT.md).

Thank you for helping improve this project!
